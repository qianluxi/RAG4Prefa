# 词表那 +0.080 到底是谁的功劳：2×2 固定池消融

生成时间：2026-10-29　代码 `c9f6d62`（其后的进度输出与重试不改变测量逻辑）
数据 `dataset.paraphrase.jsonl`（50 题）· 词表 `public_to_standard.v3.json`（28 条）·
形态 `joined` · 重排 `append` · top-k=5 · 重复 3 次
产物：`eval/reports/termmap-ablation-20261029.md`（脚本原样输出）

## 一、要回答的问题

从第四十一轮到上一轮，"词表让口语题从 0.640 到 0.720"这个数字被引用了很多次。
它是**两件事的合成**：

1. 命中的术语作为**独立通道**多召回一批候选——gold 可能因此进池；
2. 重排查询从原话换成「原话 + 术语串」——gold 在池内时可能因此往前排。

`eval.py` 只能给出"两个都开"（`rerank_parallel`）与"两个都关"（`rerank`）两行。
中间两格做不出来：基线的 `baseline_rerank_query` 有"带改写串就退回原话"的保护，
所以"池不动、只换重排查询"这一格在报告里根本不存在。

于是那个 +0.080 无法回答：该继续补词表覆盖面（召回侧），还是该改词表形态（重排侧）。
这一轮把它拆成 2×2：

|  | 重排读原话 | 重排读原话+术语串 |
|---|---|---|
| **池 = 原话** | P0Q0（= 基线 `rerank`） | P0Q1（**新的一格**） |
| **池 = +术语通道** | P1Q0 | P1Q1（= 生产形态） |

## 二、怎么做到"固定池"

同一道题的两个池**各只算一次**，池内每条候选被四种组合各打一次分。能这么省是因为
重排对池内每条独立打分、与池内顺序无关——这条写成了用例（同分除外，同分就是"谁先进
池谁在前"，`test_rerank_order_invariance_needs_unique_scores`）。

池深 25（生产值）与 50（评估口径）也不各跑一遍：融合排序与 `candidate_k` 无关，
25 池就是 50 池的前 25 条，所以从一次 50 深的全序里按池成员过滤就派生出两档。
这条也有用例，而且**测试直接调脚本的 `_ranks_at_depths`**：第一版在用例里把派生逻辑
重写了一遍，于是"把 `pool[:depth]` 改成 `pool`"这个变异从断言下面溜了过去，9 条全绿。

重排重复 3 次，主指标取多数票。原因是重排服务不位稳定：同一池三次重排，末位两个近分
候选（分差 0.001~0.02）先后会翻；14 题分母下一题就是 0.071，与要测的效应同量级。
逐题表里"重复一致"那一栏把翻动照实标出来（14 题里有 3 题在 P0Q1 上翻动）。

## 四、归因：5 题里，只靠召回 1 题、只靠重排 0 题、任一路都行 1 题、必须两者 3 题

以池深 25 为准（生产值）。P0Q0 的 9 题 → P1Q1 的 14 题，多出来的 5 题逐题对得上：

| 题 | P0Q0 | P0Q1 | P1Q0 | P1Q1 | 靠什么救回 |
|---|---|---|---|---|---|
| 不是新盖的老房子，也能用这套做法吗？ | · | · | ✓ | ✓ | **只靠术语通道** |
| 吊顶里走了管子，以后怎么检修？ | ✗ | ✓ | ✓ | ✓ | 任一路都能救 |
| 墙里的电线以后坏了能换吗？ | · | · | ✗ | ✓ | 两者同时才有效 |
| 集成吊顶里头包不包含灯具？ | · | · | ✗ | ✓ | 两者同时才有效 |
| 装修能不能把承重墙砸掉？ | ✗ | ✗ | ✗ | ✓ | 两者同时才有效 |

（`·` = gold 根本不在池里；`✗` = 在池里但排在前 5 之外。）

- **只靠术语通道**：老房子（1 题）——原话池里 gold 压根没有，术语串把它召了进来。
- **只靠重排查询**：0 题。检修那题换查询能救，但开术语通道也能，所以它不专属任何一路。
- **必须两者**：电线、吊顶灯具、承重墙（3 题）——术语通道把 gold 拉进池，但池内排序是
  原话给的，排不进前 5；换成 append 查询后才排上来。

按"从 P0Q0 出发"的加性分解读这张表要留神：池效应 (P1Q0−P0Q0) = +2、查询效应
(P0Q1−P0Q0) = +1、交互项 (P1Q1−P1Q0)−(P0Q1−P0Q0) = +2，三者和是 5，但**不是**逐题
一一对应——"检修"这题在池效应和查询效应里各算了一次（两条路都能救），交互项里的 +2
是"必须两者"的 3 题扣掉这一题的重复。逐题表比主效应表更不容易读错。

最直接的机制证据是"池内含 gold"那一列：**11/14 → 14/14**。三题的 gold 原本根本不在
候选池里，重排再准也救不回来。这正好回答上一轮那句"重排只是池深假象"——这次是独立
测量：换池之后，同一批候选池里的机会从 11 题变成 14 题。

## 五、池深 50 反而更低：0.929 < 1.000

P1Q1 在池深 25 是 14/14，池深 50 是 13/14，掉的是承重墙那题。同一份池、同一个查询，
只是池子从 25 条放大到 50 条，gold 就从前 5 掉出去。

这不是"池深 50 更差"的普遍结论，而是一个反例：**重排看到更多候选，近分竞争项也更多**。
它与上一轮"评融合类改动必须报生产池深"是同一类现象的另一面——池深不只决定"gold 进了
没进"，也决定"重排要在多少个近分项里挑 5 个"。

## 六、与历史数字对账

- 全量基线 P0Q0：池深 25 = **0.720**、池深 50 = **0.680**。这两个数与历史报告里
  口语 50 题 `rerank` 那两行（`paraphrase-50-20261029.md` 第五节）逐位相同。
  脚本不经过 `eval.py` 的 `rerank` 行，能对上说明池深、融合、重排口径一致。
- 生产形态（P1Q1）全量折算：覆盖 14 题 14/14 + 未覆盖 36 题保持基线 27/50
  = **41/50 = 0.820**（池深 25）；池深 50 为 38/50 = 0.760。
  这是算术折算（未覆盖题上 P1Q1 按定义等于 P0Q0），不是直接测量，报告里不把它写成
  "实测 0.820"。
- 上一轮那句"0.871/0.839 是重排漂移不是 rrf 与 zscore 的差"已修正：两个效应撞在
  同一对数字上。本轮的 0.643/0.714/0.786/1.000 是同一次运行里四格互相作差，
  不受跨时段漂移影响。

## 七、局限

- **只有 14 题**。一题 = 0.071，与"术语通道 +2 题"同量级；所以结论只能用"救回几题"
  表述，不能用"提升 14.3 个百分点"。
- 覆盖题的 P1Q1 打满 14/14，这个 1.000 是**上界不是估计**：它只说明"在词表认得的题上，
  两个因子全开能全部进前 5"，不说明"开词表能把任何题做到 100%"。
- 3/14 的题在 P0Q1 上三次重排名次不一致（一致的那 11 题里有 0 题翻动）。多数票压住了
  方向，但边界题的名次仍不能当精确值读。
- 池深 50 的 P1Q1 少 1 题这件事只出现一次，没有重复验证是否稳定——它可能只是那题在
  更大池子里的一次近分竞争。

## 八、结论

1. **词表的收益主要不在重排。** 单独换重排查询救回 0 题，单独开术语通道救回 1 题，
   两者一起才有效的是 3 题。重排查询不是可独立优化的旋钮——它只有在那条 gold 已经被
   术语通道召进池之后才有活干。
2. **池内覆盖率是硬约束。** 三题的 gold 原本不在池里，这一层不修，重排调到再好也没用。
   补词表的优先方向应该是"让更多题的 gold 进池"，而不是继续调重排查询形态。
3. 生产形态（`joined` + `append`）在这个池深下已把覆盖题打满，继续动形态的边际收益为 0；
   剩下的空间全在**覆盖面**——而覆盖面正是 P1-2 独立题集要量的事。
