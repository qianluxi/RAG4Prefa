# 判官改测硅基流动：v1 与 v2 的同口径对照（2026-10-30）

上一轮 `eval/refusal-judge-20261030.md` 的结论是「v1 库外 33/33、库内误拒 41/122，
不接入；v2 没测完」。没测完的原因是魔搭 API-Inference 的**魔粒**用光了：

> 每日登录 200 粒 + 绑定阿里云 50 粒，短期魔粒 **24 小时过期**，主流模型 1 粒/次
> ⇒ 一天约 250 次调用。判官全量 155 题加重试正好在 200 次上下，跑到 118 题时
> 报 `insufficient balance`（HTTP 429，语义是额度用尽**不是限流**，退避重试没用）。

本文是换到硅基流动之后的重跑。三组数字放在一起，因为**只有同模型、同候选、同一天
跑出来的两行才能相减**——这一条在上一轮已经被重排服务教训过一次。

---

## 一、先说一个会毁掉所有 A/B 的坑：同名不等于同实现

换服务商时选中了**同名**模型 `Qwen/Qwen3.5-35B-A3B`，本以为可以直接接着比。
实际第一次调用返回的是空串：

```
content = ''
completion_tokens = 202   reasoning_tokens = 200
耗时 105.3 秒
```

硅基流动上这个部署**默认开启思考**，200 token 全花在思维链上，正文一个字没输出。
判官要求"第一行可/不可、第二行理由"，拿到空串只会走格式重试，两次都是空，
最终记成"未表态"——报告上看起来是"模型不听话"，实际是没关思考。

加 `extra_body={"enable_thinking": false}` 之后：

```
content = '可\n吊顶龙骨已按荷载计算要求设计，能安全承载灯具重量。'
耗时 2.0 秒   reasoning_tokens = None
```

**同一个模型名，两个平台默认行为相反**（魔搭默认不思考）。所以：

- 换了服务商，v1 必须重跑，不能拿上一轮的 41/122 当基线；
- 这个开关不能靠人记得配，得进代码。见第五节。

## 二、结果：三组同口径对照

口径：召回方式 `rerank`、`k=5`，判官与规则闸门看**同一批冻结候选**
（`eval/reports/judge-hits.json`，本轮新检索 0 题）。库外 33 题、库内 122 题。

| 判官 | 模型 / 服务 | 库外抓到（该拒） | 库内误拒（不该拒） | 误拒率 |
|---|---|---:|---:|---:|
| v1 | 魔搭 · Qwen3.5-35B-A3B | 33/33 | 41/122 | 33.6% |
| v1 | 硅基流动 · 同名模型 | 32/33 | **32/122** | 26.2% |
| **v2** | 硅基流动 · 同名模型 | 28/33 | **4/122** | **3.3%** |

### 库外（该拒）

| 类别 | 题数 | 规则闸门 | v1@魔搭 | v1@硅基 | v2@硅基 |
|---|---:|---:|---:|---:|---:|

| `time` 跨时间 | 2 | 0 | 2 | 2 | 2 |
| `missing_topic` 库里没这个主题 | 3 | 0 | 3 | 3 | **2** |
| `near_topic` 主题相近但答不了 | 21 | 0 | 21 | **20** | **17** |
| **合计** | **33** | **7** | **33** | **32** | **28** |

### 库内（不该拒）

| 题集 | 题数 | 规则闸门 | v1@魔搭 | v1@硅基 | v2@硅基 |
|---|---:|---:|---:|---:|---:|
| `dataset`（基础） | 31 | 0 | 3 | 2 | **0** |
| `independent`（A 批） | 27 | 0 | 7 | 6 | **1** |
| `independent-b`（B 批） | 14 | 0 | 12 | 9 | **1** |

## 三、v1 换模型后救回 15 题、新错 6 题——救回的那些是判官原来读错了

只换服务商、判据完全不动（v1）的情况下，库内误拒从 41 降到 32：**15 题判"可"了，
6 题新判"不可"**。逐题看救回的 15 题，理由几乎都是"片段里确实写着那个值"：

| 问句 | 硅基 v1 引用的片段原话 |
|---|---|
| 施工图审查评分表 Q1 项满分多少？ | 明确列出 Q1"设计和应用"分组满分为 70 分 |
| 同层排水后排式座便器降板高度？ | 明确给出不宜小于 150 毫米 |
| 厨房台面做多高才不累腰？ | 提供 800mm、850mm、900mm 等具体数值 |
| 装修好的东西坏了保修多久？ | 明确给出保修期不低于 2 年、防水不低于 5 年 |
| 墙板装完要等几天做接缝收尾？ | 条板接缝处理应在门窗框、管线安装完毕 7d 后进行 |

这几道正是上一轮 v1@魔搭 判"不可"、理由是"未提供具体数值"的题。**片段里有，
判官没读到。** 所以上一轮报告里「21 题 gold 就在它看的 5 条里」那句是准确的，
不是题集的错，也不是判据的错，就是那个部署读漏了。

这层意思很重要：**判官的准确率本身会随部署漂**，和重排服务一样。所以「误拒率 34%」
这个数只能读作"在魔搭那把尺子上是 34%"，不读完这个数就换服务商，等于换了把尺子还
拿旧读数。

## 四、v2 达标了误拒，但代价落在库外拦截上

v2 按问法分型：**取值型**（多少/几天/哪个部门）必须出现同类型取值；**做法/结论型**
（会不会/能不能/怎么弄）给出对应措施就算可；两类共同保留"别的地区/年份/项目 → 不可"。

误拒从 32 掉到 **4**（3.3%），达到了上一轮定的"≤5%"目标。代价是库外从 32 掉到 **28**。

**四个误拒**（判了不可，但库里答得出）——形态与上一轮一致，都是"问结论、给要求"：

- 墙上想挂电视和吊柜，会不会掉下来？→ 片段只说"需加固或满足荷载要求"
- 装修垃圾谁负责清运？→ 片段只说"建设消纳设施及分类收集运输"
- 绍兴厨房换新，套餐超过 2 万的补多少？→ 片段给了最高 1.5 万与最低标准，没写超出部分
- 石膏板隔墙塞了岩棉隔音还是不行，哪里没做对？→ 片段只说"宜选岩棉及加强措施"

**五个漏拒**（该拒没拒）逐条判性质，这是决定能不能接入的关键：

| 题 | v2 的理由 | 性质 |
|---|---|---|
| 消防验收由哪个部门负责？ | 「可，…但未明确具体负责部门名称」 | **错判**：取值型问部门，片段没有部门 |
| 增值税税率是多少？ | 「可，…但未直接给出具体增值税税率数值」 | **错判**：取值型问数值，片段只有"含税信息价" |
| 甲醛检测该找哪家机构？ | 「可，…需委托有相应资质的第三方检测机构」 | 边界：答了"什么类型"，没答"哪一家" |
| 施工员上岗要考什么证？ | 「可，…特种作业人员需取得操作资格证书」 | **错判**：施工员不是特种作业人员，推错了对象 |
| 装修完多久能住进去？ | 「可，…验收应在完工不少于 7d 后进行」 | 边界：验收时间 ≠ 入住时间，但接近 |

**关键在头两条**：判官自己在理由里写了"未明确具体部门名称""未直接给出具体税率"，
却仍然判「可」。这说明 v2 的分型在"片段里有一个**邻近**取值"时会松——它不是没看见缺口，
是把缺口写进理由后仍然放行。也就是说：

> v1 在取值型上判得**太严**（有值也说没有），v2 在取值型上判得**太松**（没值也说有）。
> 这不是"调松调紧"能收敛的，取值型需要的是更细的判据（同类型 + 同对象），不是一句话。

## 五、工程改动

### 1. 思考开关进配置（`R4P_LLM_ENABLE_THINKING`，三态）

`Settings.llm_enable_thinking: bool | None = None`，`LLM._thinking()` 只在显式配置时
才把 `extra_body` 发出去。三态而非布尔，是因为默认值必须"什么都不发"：

- 魔搭不认识这个字段，乱发可能 400；
- 硅基流动需要 `false`，否则就是文章开头那 105 秒空响应。

`complete` / `stream` / `probe` 三处都带（`probe` 也带，否则开思考的部署上点一次
校验要等 100 秒，看起来像卡死）。`.env` 里留空要当"没配"，所以加了 before-validator
把空串/`none`/`null` 收敛成 `None`——从 `.env.example` 复制出来的文件常常保留这一行，
直接交给 pydantic 会抛 ValidationError，报错还指向一个无关字段。

### 2. 判官结论缓存的 key 加模型

原来是 `{judge}|{k}|{question}`。魔搭与硅基流动上有同名模型、行为不同，这个 key 会
**静默命中上一家的结论**——整份 A/B 就废了，而且看不出来。现在改成
`{judge}|{model}|{k}|{question}`，meta 里也记 `model`，报告口径行会打印出来。

### 3. 两套配置写进 `.env.example`

评测走硅基流动（按 token 计费，不看次数）；正式发布给普通用户走魔搭（免费，但魔粒
按天给、当天过期）。切换就是改三行 + 思考开关。`insufficient balance` 那条也写进去了：
HTTP 429 但语义是额度用尽，退避重试无效，当天刷新后自己恢复；魔粒没有购买入口，
阿里云费用中心充的钱进的是云产品，与魔粒不互通。

## 六、结论

1. **v2 达到了误拒目标（3.3%），但库外拦截从 97% 掉到 85%，所以仍然不接入阻断。**
   上一轮定的验收是"误拒 ≤5% **且** 库外拦截不塌"，前半句过了，后半句没过。
2. **可接入的是「提示」形态，不是「阻断」形态。** v2 判"不可"的只有 4 题是错的
   （3.3%），把它的结论当提示带给用户——"这几条片段可能不足以回答"——成本很低；
   反过来按它阻断，会放过 5 次本该拒答的编造风险。
3. **取值型这一支要单独做，不能靠 v2 的粗分型。** v2 的 5 个漏拒里有 3 个是取值型，
   而 v1 在取值型上误拒。两版各错一半，说明缺的是"同类型 + 同对象"的判据，不是松紧。
4. **判官数字与部署绑定。** 同一个模型名换服务商，库内误拒从 41 变 32（救 15 错 6）。
   报告里所有判官数字都要带模型与服务商，否则不可比。

## 七、可复现性

```bash
# v1（硅基流动，约 4 分钟）
python scripts/judge_sufficiency.py --judge v1 --concurrency 5 \
    --dump eval/reports/judge-v1-sf-20261030.json \
    --verdict-cache eval/reports/judge-verdicts-siliconflow.json

# v2（同上，只补缺口）
python scripts/judge_sufficiency.py --judge v2 --concurrency 5 \
    --dump eval/reports/judge-v2-sf-20261030.json \
    --verdict-cache eval/reports/judge-verdicts-siliconflow.json
```

- 候选缓存 `eval/reports/judge-hits.json` 复用（检索与 LLM 无关，换模型不影响候选）。
- 结论缓存 `judge-verdicts-siliconflow.json`，key 含模型与判官版本；`--rejudge` 才是真重判。
- 本轮判官调用失败 0 题（5 并发下偶发 `RateLimitError`，退避重试后都成功；单题失败
  记"未表态"继续，不带崩整批）。
- 遗留：① 写题人即核验人；② 判官看 5 条片段、生产 `top_k=8`，未对齐测；
   ③ `near_topic` 的"该拒"仍是相对于"我核验过的那些词"而言（子串法覆盖不到同义词）。
