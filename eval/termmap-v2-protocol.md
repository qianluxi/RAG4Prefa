# 词表 v2：构建协议（写于选词之前）

> 这份文件先于词表写成，目的是把「照条文写」和「照题目挑」分开。
> 顺序一旦反了，事后无法从结果上分辨这两种做法 —— 而上一版 8 条词表的教训正是
> 这个：它证明了「给对词这条链能通」，但 5 条是看着失败题写的，所以证明不了泛化。

## 一、要回答的问题

上一版词表在 50 题上命中 8 题（0.375 → 0.750，救 3 丢 0），但**新出的 35 题命中率 0%**
——那 8 条映射覆盖的是老 15 题的 5 个具体失败点。所以现在要回答的不是「词表有没有用」
（已经答了：有用，杠杆在重排查询），而是：

**按条文构建、不参考题目失败点的词表，能不能覆盖到没被专门瞄准的题？**

这个问题有两个可能的答案，都必须能接受：

- **能**：覆盖率和增益都超过旧表 → 说明「从语料建受控词表」是一条可复用的做法。
- **不能**：覆盖率仍低 → 说明真正的瓶颈不是词表规模，而是「哪些公众意图需要被映射」
  这件事本身依赖对失败样本的观察。这是个更有价值的负结果。

## 二、词条的三条准入判据

选词时只看语料，不看评测集：

1. **`terms` 侧必须逐字可查**：每个术语都要能在语料原文里找到，`source` 写明文档名 +
   章节号 + 原文片段。`scripts/check_term_map.py` 会机械校验这一条（找不到就是错的，
   不靠人眼）。**这一条把「模型意译的近义词」挡在门外**——而近义词正是上一轮被证伪的
   那一路（LLM 改写 15 题里 0 题复现）。
2. **`groups`（公众表达侧）必须是「条文里不会出现的说法」**：如果条文原文就这么写，
   那它不需要映射（公众已经能用原词提问）。判据是：把候选说法放进语料里搜，
   **命中数为 0 或极少**才合格。
3. **一条映射只表达一个概念**：术语侧不超过 3 个词、且必须是同一句话里的搭配。
   多概念拼在一起会让重排查询变模糊——实测重排读的是整串语义，不是词的集合。

## 三、覆盖面怎么定（不看题目）

目标是 20~30 条，按语料的五个主题域分层，每域 4~6 条：

| 主题域 | 语料里对应的章节 | 目标条数 |
|---|---|---|
| 构造与材料 | 条板/墙板、吊顶、地面、饰面、接缝 | 5~6 |
| 设备与管线 | 管线分离、排水、电气、通风、检修 | 5~6 |
| 质量验收 | 检验批、隐蔽工程、样板、保修 | 4~5 |
| 安全与防火 | 燃烧性能、结构安全、电气防护 | 4~5 |
| 补贴与政策 | 补贴标准、申领、备案、拨付、适用范围 | 5~6 |

**不看题目决定条数**：如果按题目数分，就变成「哪类题多就多写几条」，直接引入选择偏差。

## 四、评价方式（先定指标，后看结果）

1. **覆盖率**：命中词表的题数 / 总题数。分别在口语 50 题、基础 31 题上算。
2. **逐条命中统计**：每条词条命中几题。命中 0 题的是死重，要列出来。
3. **增益集中度（留一法）**：逐个删掉一条重跑，看 Recall@5 掉多少。如果全部增益
   集中在 1~2 条上，说明这份词表实质上只有 1~2 条有效，规模是假的。
4. **同条件新旧对照**：`--term-map` 分别指向 v1（8 条）与 v2，其余参数完全相同。
5. **不该被改坏的对照**：基础 31 题用的是专业问法，理论上词表不该命中；
   如果命中了且指标下降，那是误命中，比不命中更糟。

## 五、盲性说明（必须写清楚，不许含糊）

作者写过口语 50 题，也逐题看过失败点。所以这**不是双盲实验**，只能叫「准盲」，
靠四件事约束：

- 词条由语料侧驱动：`terms` 逐字可查（机械校验）、`groups` 由该领域的日常说法推出；
- 准入规则与指标在选词前写死（本文件）；
- 留一法检查增益是否集中在少数词条上——集中即视为「针对性修补」而非「规模化覆盖」；
- 每条例子的 `public_side` 字段标注来源可信度：`vernacular`（按常识写的日常说法）/
  `recalled`（动笔时已想到某道题）。**评估时把 `recalled` 的那些单独算一遍**，
  剩下那部分才是泛化证据。

第 4 条是这份协议里唯一真正能对冲作者记忆的地方，也是最该被质疑的地方。
