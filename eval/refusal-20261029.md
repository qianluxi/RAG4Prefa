# 证据闸门：什么时候该说「资料不足」（2026-10-29）

> **类别计数已过时**：库外集在 2026-10-30 从 15 题扩到 34 题（`near_topic` 由 3 题扩到 22 题，
> 见 `eval/refuse-near-topic-protocol.md`）。本文第三节「15 题拒 7 题」的四类分布以
> `eval/refusal-judge-20261030.md` 为准；本文保留的是判据设计、分数闸门实测与误拒口径，
> 这些不随题集变大而改变。

本轮按专家复审的第三条意见做：候选非空时系统凭什么作答。

先说结论：**在能命名确定性理由的三类情形里，只有一类做得到；另一类（主题缺失）在规则层做不了，
需要语义蕴含。** 下面把「做到了多少」和「为什么剩下的做不到」分开写。

---

## 一、这一层要解决的事

`prompts.SYSTEM_ANSWER` 第 3 条要求模型「片段不足就说明资料中未涉及」。那只是提示词约束：
候选一旦非空就会被递进模型，而模型很愿意基于「主题相似」的片段给一个看起来合理的答案。

扩写后的库外集（15 题，四类）在**六种召回方式下全部召回非空**：

| 类别 | 题数 | 例子 | 检索到的东西 |
|---|---|---|---|
| `geo` 跨地域 | 7 | 北京市装配化装修的补贴标准是多少？ | A3_宁波市鄞州区装配化装修试点实施方案 |
| `time` 跨时间 | 2 | 2020年发布的装配式内装修标准有哪些变化？ | 21_GB50325-2020_民用建筑工程室内环境污染控制标准 |
| `missing_topic` 库内没这个主题 | 3 | 装配式装修工人的培训证书怎么考？ | 32_装配式内装评价标准报批稿 |
| `near_topic` 主题相近但答不了 | 3 | 装修完多久能住进去？ | 21_GB50325-2020 室内环境污染控制标准 |

这不是排序误差：检索层没有「地域」「时间」「主题存在性」的概念，它只会返回最近的 k 条。

---

## 二、判据：能阻断的只有两条

实现见 `rag4prefa/sufficiency.py`，`judge()` 是纯函数，除了那次「库里有没有」的查询之外不动状态。

| 信号 | 判据 | 阻断 | 实测 |
|---|---|---|---|
| `no_hits` | 一条候选都没有 | 是 | 一直有效（原来只在 `stream_answer` 里判，现在收拢到一处） |
| `geo_absent` | 问句点名的地域，库里没有**一份关于它的文件** | 是 | 地域类 7/7 |
| `weak_top` | 最相关候选的分数低于门槛 | 可配，**默认关** | **实测不可用**，见第四节 |

### 为什么用文件名而不是正文

这是本轮最容易做错的一处，也是第一版写错的地方：一开始用「全库正文有没有提过这个地名」。

实测本库 75 份文件、2560 个片段：

| 地名 | 正文提到的片段数 | 有以它为题的文件 |
|---|---:|---:|
| 北京 | 17 | 0 |
| 上海 | 11 | 0 |
| 深圳 | 9 | 0 |
| 广东 | 6 | 0 |
| 江苏 | 2 | 0 |
| 日本 | 2 | 0 |

正文里出现地名，绝大多数是顺带一提——参编单位名单（"上海深海宏添建材有限公司"）、
企业简介（"承建了北京 APEC 峰会"）、区域规划（"积极接轨上海"）。拿正文判断，闸门对这一整类
**永远不会触发**，而且不会报错，只会安静地全部放行。

改成文件名口径后，本库的「地域覆盖」是：浙江 22 份、绍兴 7、宁波 5、台州 4、杭州 3、湖州 2、嘉兴 1
——正好就是语料真实覆盖的范围。

### 为什么不拿「问句里的词在候选里找不到」当判据

这是最像「证据充分性」的做法，也是最危险的一个。口语题里词形对不上是常态：
「有味道上来」对应「返味」、「看到水印」对应「渗漏」、「补多少」对应「补贴」。
拿词形覆盖率阻断，会把大量本来答得出的题一起拒掉——那是把一种静默错误换成另一种，
而且这次错在用户那边（他问的东西明明在库里）。

上一轮独立题集的结论正是这个：41 题里按语义**该**命中词表的有 9 题，实际认出 1 题。
判据连「该不该命中」都认不准，更不该拿它决定「能不能答」。

## 三、结果

### 库外集：15 题拒 7 题，全部来自地域类

六种召回方式的结果完全一致（拒答判定看「问句 + 候选所属文件」，与召回路径无关）：

| 类别 | 拒答/题数 |
|---|---|
| `geo` 跨地域 | **7/7** |
| `time` 跨时间 | 0/2 |
| `missing_topic` 库内没这个主题 | 0/3 |
| `near_topic` 主题相近但答不了 | 0/3 |
| 合计 | 7/15 |

### 库内集：误拒 0

误拒比漏拒更贵——用户问的东西明明在库里。四份题集、六种召回方式，**误拒全为 0**：

| 题集 | 题数 | 误拒（dense / dense_rerank / hybrid / rerank / hybrid_parallel / rerank_parallel） |
|---|---|---|
| 基础 31 题 | 31 | 0 / 0 / 0 / 0 / 0 / 0 |
| 口语 50 题 | 50 | 0 / 0 / 0 / 0 / 0 / 0 |
| 独立 A 批 | 27 | 0 / 0 / 0 / 0 / 0 / 0 |
| 独立 B 批 | 14 | 0 / 0 / 0 / 0 / 0 / 0 |
| 合计 | **122** | 全部 0 |

数据来自各题集本轮从干净提交（`db99c1e`，源码 sha `6cd2081a5024`）重跑的报告末节。
这不是「闸门很保守所以不误伤」，而是它的判据只在**问句点名了库里完全没有的地域**时动手；
库内题里出现的浙江各市（浙江/绍兴/宁波/台州/杭州/湖州/嘉兴）都在文件名里。

### 拒答时长什么样

不是「我拒绝回答」，而是把缺的东西说清楚：

> 资料不足，暂不能据此作答：问句问的是「北京」，而库里没有一份资料是关于它的；
> 只凭主题相近的片段作答，会把别处的规定当成这个地域的规定。

前端状态栏同步显示理由（`web/index.html`），因为「模型不想答」与「检索层判定没有资料」
是两件不同的事，责任人也不一样。

## 四、分数闸门：实测不可用，所以默认关

`weak_top` 的想法是「最相关的那条分数低到连沾边都算不上」。用 `scripts/calibrate_refusal.py`
在当天服务上量了 122 道库内题与 15 道库外题的 top1 分：

| 组 | 题数 | min | p10 | 中位 | p90 | max |
|---|---|---|---|---|---|---|
| 库内（有 gold） | 122 | **0.2692** | 0.9702 | 0.9992 | 0.9999 | 1.0000 |
| 库外（该拒） | 15 | 0.8312 | 0.9677 | 0.9992 | 0.9999 | 0.9999 |

两个分布**完全重叠**，库内最低分反而比库外最低分更低。逐题看更清楚：

- 库外题 top1 常常 0.999+：「北京补贴标准」0.9996、「江苏装配率怎么算」0.9999；
- 库内题反倒有低分：「卫生间地漏那股味道」0.2692、「厨房吊顶能不能拆装」0.7159。

也就是说这个重排服务对「主题沾边但答不了」的题照样给高分——它判的是「这段文字与这个问题
是否相关」，不是「这段文字能否支持一个答案」。**不存在一个能把这批分开的单一门槛。**

所以 `refuse_min_rerank` / `refuse_min_dense` 默认 0（= 不设分闸），并在 `config.py` 里写清
这是实测结论而不是偷懒。换重排或 embedding 模型后必须用同一个脚本重量，否则这两个数是别人
那套模型的分布。

## 五、没做到的部分，以及下一步该怎么做

剩下的 8 题（`time` 2 + `missing_topic` 3 + `near_topic` 3）仍然会被作答。它们要求的判据是
**「这批片段能不能支持这个答案」**，那是语义蕴含，规则层做不到。两条可选路径：

1. **LLM 判官（推荐先做）**：在回答之前单独问一次「给定这些片段，问题能被回答吗？只回 可/不可
   + 一句理由」，与回答用不同的提示词。它与现有「在提示词里求模型别猜」的区别是可独立评估：
   判官的输出可以逐题核对，误判能归因到具体题，而提示词的效果无法从答案里分离出来。
   代价是每题多一次 LLM 调用。
2. **条文级证据对齐**：把问句拆成「主体 + 属性 + 取值类型」，检查候选里有没有对应的取值
   （数值、单位、部门名）。这条能覆盖 `near_topic` 的一部分（问"多久"而候选里没有任何时长），
   但拆解本身又要靠模型，等价于路径 1 的弱化版。

两条都需要一个新的验收集：**「主题相近但答不了」这一类必须再扩**（现在只有 3 题，
而它是这一层真正的目标）。这批题也必须由没看过检索结果的人写——否则又会变成挑好写的。

## 六、顺带修掉的与行为变化

- **年份过滤器**（`filters.py`）：`到2027年，老旧住宅电梯要怎么处理` 不再被当成「只看 2027 年的
  文件」。判据从「见到 20XX年 就筛」改成「年份后面紧跟资料标记才筛」，并补了六条回归用例
  （目标年、历史年、发文年、同句多年份）。
  行为变化：`2026年省里对建筑业监管有什么安排` 这类「年份在句首、后面不接资料名词」的问句
  不再缩小范围——候选池变大，该由排序承担，而不是由过滤器静默清空。
- **识别稿体检重跑**（`eval/ocr-audit-20261029.md`）：13 份识别稿、4 份有具体线索（GB55037 五处
  条文断档、GB50210 一处断档 + 表 15.0.6 缺表头、DBJ33T1165 与 JGJT477 各一处）。
  对照 103 个 gold：**只有 1 个落在断档章节内**（且它本身在库里），**20 个 gold 来自识别稿文档**。
  后一个数字要记住：评测里有 19% 的 gold 依赖视觉模型认字的质量。

## 七、遗留

1. 地域表是手写的（`sufficiency.PLACES`，约 90 个地名）。它只覆盖「常见省市 + 浙江各市」，
   问「衢州」「嵊州」这类库里有文件但表里没有的地名，闸门不会出手——这是已知的漏，
   而不是误判（漏的方向与设计一致）。
2. `geo_absent` 只判「有没有关于它的文件」，不判「这份文件是不是现行」。问「2020年的版本」时
   库里可能有该文件，闸门放行——这类需要文件元数据（状态、废止日期），目前没有。
3. 门槛默认 0 依赖「这个重排服务判不了能不能答」这一实测结论。换模型必须重量。
4. `geo_absent` 查的是**全库**，不是当前筛选范围。用户把范围限到某个项目 A、而「北京」只出现在
   项目 B 的文件名里时，闸门会放行——它问的是"库里有没有"，不是"这次检索有没有"。
   评测里筛的都是全库（`projects: 装配式内装`），所以这个差别没被量到，属于已知未修。
